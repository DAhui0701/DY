# 直播经营台

一个中文直播经营工作区，使用 HTML、CSS、JavaScript。本版支持在浏览器中读取抖音电商罗盘的“收支分析”Excel，查看经营总览、每日趋势及原始数据。不连接平台或 AI 接口，不需要登录。

## 已实现与尚未实现

- **报表导入**：选择 `.xlsx`，检查全部工作表和必需字段；展示文件名、实际日期范围、各表名称、字段数和记录数。
- **原始数据**：切换工作表，查看全部字段；每页 50 条，可翻页和左右滚动，保留原文件行号。
- **导入核对**：可展开查看全店统一口径下的成交金额、结算金额和支出金额，避免重复汇总。
- **经营总览**：与同一份导入结果联动，支持日期及已有维度筛选、指标口径说明、每日趋势、可核对明细和规则式经营提示。
- **直播复盘**：仍为占位，本次不制作完整复盘系统。
- 没有数据时保留空状态，没有虚构经营指标。

## 怎样打开

下载整个项目文件夹，用 Edge 或 Chrome 打开 `index.html`。不要只下载 HTML；需要同时保留 CSS、所有 JavaScript 文件（包括新增的 `overview.js`、`overview-ui.js`）和整个 `vendor/` 文件夹。无需安装依赖或填写密钥。

如果浏览器限制直接打开本地文件，可在自己的电脑安装 Python 3，在项目文件夹内打开终端并执行：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

Windows 也可以使用：

```bash
py -m http.server 8000 --bind 127.0.0.1
```

随后在自己电脑的浏览器输入 `http://127.0.0.1:8000`。按 `Ctrl+C` 停止。云端的本地地址不等于自己电脑的本地地址。

这个临时服务只用于本机开发，不要对外公开；它可能提供目录内被 Git 忽略的文件，所以真实报表应放在项目目录之外。导入按钮可选择项目之外的文件，无需先把报表复制进项目。

## 怎样导入和查看

1. 使用从罗盘导出的标准 `.xlsx`，包含“收支分析”和“账号收支详情”。第一行应为单行完整表头。
2. 在“报表导入”中点击文件选择按钮。程序会读取并检查全部工作表；读取时暂时禁用选择按钮，避免并发导入。
3. 成功后查看文件名、日期范围、表名和记录数。日期来自单元格，记录数不包含表头和全空行。
4. 展开“查看导入金额核对与汇总口径”，核对全店金额。不能把原始表的全部行相加。
5. 在“原始数据”下拉框切换工作表。表格可左右滚动查看全部字段，用“上一页”“下一页”浏览全部记录。
6. 原始表按文件顺序显示。空白单元格显示“（空）”；`-` 保留原值，不转成零。公式不执行，单元格中的链接或 HTML 文本不作为可执行内容。

### 替换、重复与失败

- 第一版只保留一份当前文件，导入另一份文件会替换全部工作表，不追加、不累计。
- 已有数据时，读取新工作簿前会弹出替换提示。取消后原数据不变。
- 所有工作表校验成功后才替换数据。任意表失败都会保留上一份有效数据，并显示中文原因；不要把失败提示当成已经更新成功。
- 通过文件内容逐字节比对识别重复文件。相同文件改名后再次选择也会跳过。编辑过内容的文件视为新文件，仍需确认替换。
- 重复判断只针对当前页面中的当前文件，不保存历史导入列表；因为不做追加，重导旧文件也不会叠加收入。

### 数据是否上传和保存

**文件及经营数据只在当前浏览器页面内存中处理。**

- 不上传到服务器、平台、AI 或其他网站。
- 不写入 localStorage、sessionStorage、IndexedDB、Cookie 或项目文件。
- 不自动下载或保存导入结果，不修改源 Excel。
- 刷新或关闭页面后需要重新选择文件。原 Excel 仍在你电脑上，程序不会删除它。
- 页面资源和 Excel 读取库均为项目本地文件；导入不发起外部接口请求。

## 支持范围及中文提示

支持此类罗盘收支分析报表，两个标准工作表各有 43 个必需字段。允许字段换序、新增字段及额外工作表；未知工作表只原样展示，不参与金额核对。详细字段见 [字段与汇总规则](docs/report-format.md)。

| 情况 | 页面行为 |
| --- | --- |
| 缺少必需工作表或字段 | 指出缺少项，拒绝替换 |
| 表头为空、重复或不是首行单行表头 | 提示表头问题，拒绝替换 |
| 金额为空、非数字、超过两位小数或包含公式 | 指出表名、原文件行号、字段，拒绝替换 |
| 合法负数金额 | 保留并正确核对，不当作异常 |
| 不存在的日期、无法识别日期或未来日期 | 提示日期异常，拒绝替换 |
| 日期不连续、两表日期覆盖不一致 | 成功读取后提示，不补零 |
| 文件名日期与实际日期不符 | 提示差异，以记录日期为准 |
| 已识别表中出现重复日期与维度组合 | 提示重复记录，拒绝替换 |
| 比率/效率字段为 `-` | 保留未提供值，不视为零 |
| 比率/效率字段为非数字且不是 `-` | 提示无效字段，拒绝替换 |
| 空文件、只有表头、损坏文件、错误格式 | 提示中文原因，保留旧数据 |

当前不支持 `.xls`、`.xlsm`、CSV、加密文件、ZIP64、合并/多行表头、公式计算、多个文件合并及任意类型的 Excel。请直接使用平台标准导出，不要只改扩展名。

只接受最多 10 MB 的文件；解压声明大小最多 40 MB、最多 20 张表、每表最多 25000 行（含表头）、200 列、全部工作表合计最多 50 万个矩形范围单元格。超过限制时请缩小导出日期范围。读取在浏览器主线程中进行，较大文件可能短暂卡顿；请只导入可信来源的报表。

## 为什么不能直接相加

“收支分析”包含日期、经营类型、载体类型、推广时段四个维度。同一天的“全店”“自营”“合作”存在汇总和细分关系，“全部”和具体载体、“不限”和具体时段也存在包含关系。

因此全店金额核对只取“全店＋全部＋不限”，每个日期一条，再跨日期加总同一个金额字段。“账号收支详情”不能与全店表再相加。金额按整数“分”计算，避免浮点累计误差。比率与效率不求和或简单平均。

报表没有订单数、支付人数、观看人数、广告归因成交、直播场次标识、商品成本等必要字段，所以对应人数/归因指标明确显示“无法计算”，不生成准确场次或净利润。7日、14日结算金额不与普通结算金额叠加；支付时间与退款时间口径分别保留。

## 怎样使用经营总览

1. 在“报表导入”选择真实 Excel，成功后点击导航中的“经营总览”。无需再次上传，两个模块共用同一份数据。
2. 顶部核对文件名、文件日期范围、本地导入时间。平台更新时间/退款数据截至时间如未提供会明确标注，不能用导入时间替代。
3. 选择开始和结束日期，修改筛选后自动更新。
4. 店铺视图可选择实际存在的经营类型、载体和推广时段。默认只取“全店＋全部＋不限”，不重复累计细分行。
5. 切换“单个账号”后选择实际账号。账号表没有载体和推广时段维度，相应筛选禁用，直播成交显示无法计算，不以全店数据代替。
6. 可切换“店铺被投/店铺绑定”消耗及“支付时间/退款时间”退款口径。注意：退款发生时间金额不计算本期退款率。
7. 每张卡片显示单位、公式和说明；展开“来源与汇总规则”查看来源表、字段和当前筛选。
8. 趋势优先展示成交、退款、消耗。数据点可悬停或聚焦，下面每日明细可查精确金额及原文件行号。手机可在图表、表格自身区域左右滚动。
9. 缺日期时不补零，也不把部分已知金额当成完整区间合计；可以缩小到完整日期范围后核对。
10. “恢复默认范围”恢复当前文件的全期间与默认口径；新文件成功替换时也自动重置全部总览结果。

### 指标口径一览

| 指标 | 计算方式与限制 |
| --- | --- |
| 成交金额 | 选定日期、维度下每天一条记录的成交金额求和 |
| 直播成交金额 | 同日期、经营类型和推广时段，载体固定为直播；非直播筛选或账号视图不混用范围 |
| 投放消耗 | 使用已选“店铺被投”或“店铺绑定”，不将两者相加 |
| 成交退款金额 | 使用已选支付时间或退款时间字段，不混合两种口径 |
| 成交退款金额占比（支付时间） | 同范围支付时间口径成交退款金额÷成交金额；仅本次导出快照，后续退款可能改变结果，平台截至时间未提供 |
| 整体成交消耗比 | 同范围成交金额÷消耗；包含自然成交，不等于广告归因投产比 |
| 支付转化率 | 缺支付人数、观看/访问人数和区间去重依据，无法计算 |
| 人均客单价 | 应为支付金额÷去重支付人数；当前缺人数，无法计算，不用订单均价替代 |
| 广告归因投产比 | 缺归因成交和对应广告消耗匹配口径，无法计算 |

金额用整数“分”计算，比率先汇总同口径分子分母再求比，四舍五入到两位；不平均每日比例。分母为 0、字段缺失、日期缺失或口径不匹配时给出原因。金额和比值均不是利润；不显示虚构同比、环比。

经营提示只基于当前数据触发固定规则，每条包含事实、待核实问题、动作和验证指标。退款占比达到 50% 仅作为本页排查提示线，不是行业标准；不会直接认定主播话术、产品质量或履约问题。直播零成交先核实停播、数据缺失或范围变化。

详细定义见 [经营总览指标与限制](docs/overview-metrics.md)。

## 怎样验收

请用你自己的报表在本机执行：

1. 刚打开时导入、总览和原始数据应为空，不出现虚构指标。
2. 导入完整报表，对照 Excel 核对两个工作表的字段和记录数，记录数不包含表头。
3. 在 Excel 中筛选“全店＋全部＋不限”，求和成交金额、结算金额和支出金额，与页面展开的核对金额比较。不要直接求和全部行。
4. 切换两张表，左右滚动并翻页，核对首条、末条记录和原文件行号。
5. 再次选择相同文件，再将同一文件复制并改名后选择，都应提示内容相同，不增加记录。
6. 选择另一份文件并取消替换，确认仍显示旧文件。
7. 使用副本测试缺字段、错误金额、无效日期；确认有中文提示，旧文件仍可查看。不要修改你的原始报表。
8. 选择空文件或非 Excel 文件，确认错误不会清除有效数据。
9. 导入另一份有效报表，确认替换而非累计。
10. 刷新页面，确认数据清空，需要重新导入。
11. 缩窄浏览器窗口检查手机布局；表格应在自身区域滚动，不撑宽整个页面。

总览还应验收：全期间与单日金额、经营类型/载体/推广时段、单账号、两种消耗和退款口径；零分母、无匹配日期、缺失日期、来源说明、趋势与每日明细。换文件成功应重置全部总览，失败或取消时旧结果不变。

## 保护真实数据与查看改动

真实报表优先放在项目目录之外。`.gitignore` 已忽略常见 Excel/CSV、密钥和以下本地目录：`reports/`、`data/`、`local-data/`、`uploads/`、`exports/`、`private/`、`attachments/`。

JSON、图片、PDF 等真实数据请放在这些目录内或仓库之外，不要把包含经营数据的截图或测试结果加入提交。忽略规则不是加密；它不会移除已跟踪文件，也不能阻止强制添加。

```bash
# 查看本次文件状态
git status --short
# 查看已跟踪文件的未暂存改动；新文件可直接打开阅读
git diff
```

确认无敏感信息后，只添加明确的源代码、文档、测试及第三方库：

```bash
git add index.html styles.css app.js report.js overview.js overview-ui.js .gitignore README.md docs/ tests/ vendor/
git diff --cached
git commit -m "实现同源经营总览和指标口径说明"
```

`commit` 保存本地版本，尚未上传。若当前为开发分支，可执行 `git push -u origin HEAD` 上传，再到 GitHub 创建 Pull Request，检查后合并到 `main`。推送需要 GitHub 写入权限。不要使用强制添加或强制推送。本次开发不会自动提交或推送。
